# MirageCodes

**Система промокодов для Paper 1.21.4+** — игрок вводит `/code <промокод>` и получает награду.
Награды выдаются **командами** и **предметами**, плюс сообщения, титры, звуки и объявления.
Лимиты, сроки, права, шансы, защита от перебора, генератор одноразовых кодов, лог и уведомления в Discord.

## Возможности

| Что | Описание |
|---|---|
| Команда `/code` | Алиасы: `/promocode`, `/код`, `/промокод` |
| Награды-команды | От имени консоли или игрока, с плейсхолдерами |
| Награды-предметы | Простые (материал, количество, название, лор, зачарования) или **любой предмет из руки целиком** |
| Другие награды | Сообщение, объявление на весь сервер, титр, звук |
| Шанс | У каждой награды свой `chance` (в процентах) |
| Задержка | У каждой награды свой `delay` (в тиках) |
| Лимиты | Общий лимит на код и лимит на каждого игрока |
| Сроки | Дата начала и окончания действия |
| Права | Для кода можно требовать своё право |
| Регистр | Учитывать регистр кода или нет (для каждого кода отдельно) |
| Защита от перебора | Блокировка после N неверных попыток, задержка между попытками |
| Инвентарь | Режим «выбросить остаток» или «не активировать, пока нет места» |
| Генератор | Сотни одноразовых кодов по шаблону, список сохраняется в файл |
| Управление | Всё настраивается командами в игре **или** правкой `codes.yml` |
| Лог | Файл `redeems.log` и необязательный Discord webhook |
| Цвета | `&c`, `&f`, HEX `&#RRGGBB`; оформление по умолчанию — красный + белый |

## Требования и установка

- **Paper 1.21.4** или новее (на Spigot не работает: используется Paper API).
- **Java 21**.

Установка:

1. Положите `MirageCodes-*.jar` в папку `plugins/`.
2. Перезапустите сервер (не `/reload`).
3. Появится папка `plugins/MirageCodes/` с `config.yml` и `codes.yml`.
4. Настройте коды (командами или файлом) и выполните `/mcodes reload`, если правили файлы.

> В `codes.yml` лежат **примеры** (`WELCOME`, `MIRAGE`, `LUCKY`, `VIP-GIFT`). Удалите их, когда сделаете свои:
> `/mcodes delete WELCOME` и так далее.

## Быстрый старт за 2 минуты

Создадим код `SUMMER`: 5 алмазов + сообщение, каждому игроку один раз, всего на 50 человек, неделя действия.

```
/mcodes create SUMMER
/mcodes addcmd SUMMER give %player% diamond 5
/mcodes addmsg SUMMER &fЛето пришло, &c%player%&f!
/mcodes setuses SUMMER 50
/mcodes setperplayer SUMMER 1
/mcodes setexpire SUMMER 7d
/mcodes info SUMMER
```

Игрок вводит: `/code SUMMER` — готово.

Выдать **предмет из руки** (с названием, зачарованиями и всеми данными):

```
/mcodes additem SUMMER
```

Выдать предмет по названию: `/mcodes additem SUMMER GOLDEN_APPLE 3`.

## Команды

### Для игроков

| Команда | Описание | Право |
|---|---|---|
| `/code <промокод>` | Активировать промокод | `miragecodes.use` |

Алиасы: `/promocode`, `/код`, `/промокод`.

### Для администраторов

Основная команда: `/miragecodes`, алиасы: `/mcodes`, `/mcode`. Нужно право `miragecodes.admin`.

| Команда | Описание |
|---|---|
| `/mcodes help` | Справка |
| `/mcodes create <код>` | Создать код. ID: 2–32 символа — буквы (в том числе русские), цифры, `_` и `-` |
| `/mcodes delete <код>` | Удалить код вместе со статистикой использований |
| `/mcodes list [страница]` | Список кодов с числом использований |
| `/mcodes info <код>` | Все настройки и список наград с номерами |
| `/mcodes toggle <код>` | Включить / отключить код |
| `/mcodes setuses <код> <число\|unlimited>` | Общий лимит использований |
| `/mcodes setperplayer <код> <число\|unlimited>` | Лимит на одного игрока |
| `/mcodes setexpire <код> <дата\|длительность\|never>` | До какого времени действует |
| `/mcodes setstart <код> <дата\|длительность\|none>` | С какого времени действует |
| `/mcodes setperm <код> <право\|none>` | Требуемое право |
| `/mcodes setcase <код> <true\|false>` | Учитывать регистр |
| `/mcodes setmessage <код> <текст\|none>` | Своё сообщение об успешной активации |
| `/mcodes addcmd <код> [console\|player] <команда>` | Добавить награду-команду (по умолчанию от консоли) |
| `/mcodes additem <код>` | Добавить предмет из основной руки (сохраняется целиком) |
| `/mcodes additem <код> <МАТЕРИАЛ> [количество]` | Добавить простой предмет |
| `/mcodes addmsg <код> <текст>` | Сообщение игроку |
| `/mcodes addbroadcast <код> <текст>` | Объявление на весь сервер |
| `/mcodes rmreward <код> <номер>` | Удалить награду (номер из `info`) |
| `/mcodes reset <код> [игрок]` | Сбросить использования (всем или одному игроку) |
| `/mcodes generate <шаблон> <кол-во> [длина] [префикс]` | Сгенерировать одноразовые коды |
| `/mcodes reload` | Перезагрузить `config.yml` и `codes.yml` |

**Форматы дат** для `setexpire` / `setstart`:

| Пример | Значение |
|---|---|
| `2026-12-31 23:59` | Точная дата и время |
| `31.12.2026 23:59` | То же, российский формат |
| `2026-12-31` / `31.12.2026` | Начало этого дня (00:00) |
| `30m`, `12h`, `7d`, `2w` | Через 30 минут / 12 часов / 7 дней / 2 недели **от текущего момента** |
| `never` / `none` | Не ограничено |

Дата считается в часовом поясе из `settings.timezone`.

Подсказки по Tab работают для подкоманд и ID кодов. Сами коды в `/code` намеренно **не подсказываются**.

## Права

| Право | По умолчанию | Описание |
|---|---|---|
| `miragecodes.use` | все | Пользоваться `/code` |
| `miragecodes.admin` | OP | Управление через `/mcodes` |
| `miragecodes.bypass.cooldown` | OP | Нет задержки между попытками |
| `miragecodes.bypass.lockout` | OP | Нет блокировки за неверные коды |

Кроме этого, у каждого кода может быть **своё право** (параметр `permission`), например `miragecodes.vip`.
Выдать его можно через LuckPerms: `/lp group vip permission set miragecodes.vip true`.

## Файлы плагина

| Файл | Назначение |
|---|---|
| `config.yml` | Настройки и **все сообщения** |
| `codes.yml` | Промокоды и их награды |
| `usage.yml` | Счётчики использований (служебный, вручную не править) |
| `redeems.log` | Журнал активаций (если включён) |
| `generated/` | Списки кодов, созданных `/mcodes generate` |

> Правите `codes.yml` вручную — делайте это аккуратно и затем `/mcodes reload`.
> Команды `/mcodes ...` пересохраняют `codes.yml` целиком, поэтому **комментарии в файле при этом пропадают** — это нормально.

## Формат codes.yml

```yaml
codes:
  SUMMER:                          # ID промокода — то, что вводит игрок
    enabled: true                  # включён ли код
    case-sensitive: false          # учитывать регистр при вводе
    max-uses: 50                   # общий лимит (-1 = без ограничений)
    max-uses-per-player: 1         # лимит на игрока (-1 = без ограничений)
    start: none                    # когда начинает действовать
    expires: "2026-12-31 23:59:00" # когда перестаёт действовать (never = бессрочно)
    permission: ""                 # право, нужное для активации (пусто = без права)
    message: ""                    # своё сообщение об успехе (пусто = стандартное)
    rewards:                       # список наград, см. ниже
      - type: command
        command: "give %player% diamond 5"
```

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `enabled` | true/false | `true` | Отключённый код ответит «Этот промокод отключён» |
| `case-sensitive` | true/false | из `settings.case-sensitive-default` | `true` — `Summer` и `SUMMER` разные |
| `max-uses` | число | `-1` | Сколько раз код можно активировать **всего** |
| `max-uses-per-player` | число | `1` | Сколько раз его может активировать **один игрок** |
| `start` | дата / `none` | `none` | До этого момента код отвечает «ещё не активен» |
| `expires` | дата / `never` | `never` | После этого момента код отвечает «срок истёк» |
| `permission` | строка | пусто | Право, без которого код не активируется |
| `message` | строка | пусто | Заменяет стандартное сообщение об успехе; работают цвета и плейсхолдеры |
| `rewards` | список | пусто | Награды, выдаются в порядке списка |

> **Даты пишите в кавычках**: `"2026-12-31 23:59:00"`. Относительные значения (`7d`) в файле **не работают** — только в командах.
> Если дата в файле неверная, код будет отключён, а в консоль придёт предупреждение.

> Два кода, отличающиеся только регистром (`Summer` и `SUMMER`), одновременно существовать не могут.

## Типы наград

Каждая награда — это блок в списке `rewards` с полем `type`. У **любой** награды можно задать:

| Поле | Описание |
|---|---|
| `chance` | Шанс выдачи в процентах (по умолчанию `100`). Например `25` — выпадет в четверти случаев |
| `delay` | Задержка перед выдачей в тиках (`20` тиков = 1 секунда). По умолчанию `0` |

### `command` — команда

```yaml
- type: command
  as: console                      # console (по умолчанию) или player
  command: "give %player% diamond 5"
```

- `as: console` — команду выполняет консоль (можно любые команды, например экономики, LuckPerms и т.д.).
- `as: player` — игрок выполняет команду от своего имени (с его правами).
- Слеш в начале необязателен.

### `item` — предмет

Вариант 1 — **простой предмет**:

```yaml
- type: item
  material: DIAMOND_SWORD
  amount: 1
  name: "&c&lМеч Миража"
  lore:
    - "&fНаграда за промокод"
    - "&fВладелец: &c%player%"
  enchantments:
    - "sharpness:5"
    - "unbreaking:3"
  unbreakable: true
```

| Поле | Описание |
|---|---|
| `material` | Название материала Bukkit (`DIAMOND`, `GOLDEN_APPLE`, `ENCHANTED_BOOK` и т.д.) |
| `amount` | Количество (1–2304; большие стаки сами разбиваются) |
| `name` | Название, поддерживает цвета и плейсхолдеры, курсив отключён |
| `lore` | Список строк описания |
| `enchantments` | Список `название:уровень`, например `sharpness:5`. Для `ENCHANTED_BOOK` зачарования кладутся в книгу. Допустим и вариант `minecraft:sharpness:5` |
| `unbreakable` | `true` — неразрушаемый |

Вариант 2 — **предмет целиком** (рекомендуется для сложных предметов: кастомные модели, атрибуты, NBT, зелья, головы и т.д.):

1. Возьмите предмет в основную руку.
2. Выполните `/mcodes additem <код>`.
3. Плагин сохранит предмет в поле `item-data` (длинная строка Base64):

```yaml
- type: item
  item-data: "H4sIAAAAAAAA..."
```

Эту строку вручную не редактируют. Название и лор в `item-data` **не** проходят через плейсхолдеры.

### `message` — сообщение игроку

```yaml
- type: message
  text: "&fСпасибо за промокод, &c%player%&f!"
```

### `broadcast` — объявление на весь сервер

```yaml
- type: broadcast
  text: "&c%player% &fактивировал промокод &c%code%&f!"
```

### `title` — титр на экране

```yaml
- type: title
  title: "&c&lMirage"
  subtitle: "&fНаграда получена"
  fade-in: 10                      # тики
  stay: 60
  fade-out: 10
```

### `sound` — звук

```yaml
- type: sound
  sound: "entity.player.levelup"   # ключ звука Minecraft
  volume: 1.0
  pitch: 1.0
```

Список звуков: <https://minecraft.wiki/w/Sounds.json>. Запись вида `ENTITY_PLAYER_LEVELUP` тоже понимается.

## Плейсхолдеры

Работают в `command`, `message`, `broadcast`, `title`, в названии и лоре простых предметов и в поле `message` кода.

| Плейсхолдер | Значение |
|---|---|
| `%player%` | Ник игрока |
| `%uuid%` | UUID игрока |
| `%code%` | ID промокода |
| `%uses%` | Сколько раз код активирован всего (включая эту активацию) |
| `%max%` | Общий лимит кода (`∞`, если без ограничений) |
| `%player_uses%` | Сколько раз этот игрок активировал код (включая эту активацию) |

Сторонние плейсхолдеры (PlaceholderAPI) **не поддерживаются**.

---

## Цвета

- Стандартные: `&c` — красный, `&4` — тёмно-красный, `&f` — белый, `&7` — серый, `&8` — тёмно-серый, `&l` — жирный, `&m` — зачёркнутый, `&r` — сброс.
- HEX: `&#FF3B3B`.
- Оформление по умолчанию: основа — белый `&f`, акценты — красный `&c`.

Любое сообщение в `config.yml` можно сделать пустым (`""`) — тогда оно не отправляется.

## Настройки config.yml

```yaml
settings:
  case-sensitive-default: false   # регистр для НОВЫХ кодов
  cooldown-seconds: 3             # пауза между попытками /code (0 = нет)
  max-failed-attempts: 5          # неверных кодов подряд до блокировки (0 = выключено)
  lockout-seconds: 120            # длительность блокировки
  inventory-full: drop            # drop | deny
  timezone: system                # или Europe/Moscow
  date-format: "dd.MM.yyyy HH:mm" # как показывать даты в сообщениях
  autosave-seconds: 30            # автосохранение счётчиков
  console-log: true               # писать активации в консоль
  log-redeems: true               # писать активации в redeems.log
  sounds:
    success: { sound: "entity.player.levelup", volume: 1.0, pitch: 1.2 }
    fail:    { sound: "entity.villager.no",    volume: 1.0, pitch: 1.0 }
  discord-webhook:
    enabled: false
    url: ""
    content: "🎁 **%player%** активировал промокод **%code%** (%uses%/%max%)"
```

Раздел `messages` содержит **все тексты плагина** (русский язык). Плейсхолдеры в сообщениях: `%label%`, `%time%`, `%left%`, `%date%`, `%max%`, `%code%` и другие — смотрите готовый файл.

После правки выполните `/mcodes reload`.

## Защита от перебора

- Между попытками `/code` действует пауза `cooldown-seconds`.
- После `max-failed-attempts` **неверных** кодов подряд игрок блокируется на `lockout-seconds`. В консоль пишется предупреждение.
- Успешная активация обнуляет счётчик неверных попыток.
- Сообщения «отключён», «срок истёк», «лимит исчерпан» **не считаются** неверными попытками.
- OP по умолчанию имеют `miragecodes.bypass.cooldown` и `miragecodes.bypass.lockout`.
- Слишком длинный ввод (больше 64 символов) считается неверным кодом.

> Для кодов, которые нельзя угадать, используйте генератор: 10 символов дают огромное число комбинаций.

## Инвентарь заполнен

Если награда содержит предметы, а места нет:

- `inventory-full: drop` — остаток выпадает рядом с игроком, ему приходит сообщение `inventory-full-drop`.
- `inventory-full: deny` — код **не активируется**, использование **не списывается**, игрок получает `inventory-full-deny` и может повторить после освобождения места.

В режиме `deny` проверяются предметы, которые выпали по шансу в этой попытке. Предметы с `delay` тоже учитываются.

## Одноразовые коды (генератор)

```
/mcodes generate <шаблон> <количество> [длина] [префикс]
```

- `шаблон` — существующий код: его награды, срок, право и прочие настройки копируются.
- `количество` — от 1 до 1000.
- `длина` — случайная часть, от 4 до 24 символов (по умолчанию 10).
- `префикс` — до 16 символов (буквы, цифры, `_`), добавляется перед кодом через `-`.
- У каждого сгенерированного кода **общий лимит = 1** (одноразовый).
- Список сохраняется в `plugins/MirageCodes/generated/<шаблон>-<время>.txt` — по одному коду в строке.

Пример: `/mcodes generate SUMMER 100 8 GIFT` создаст коды вида `GIFT-K7M2QXWA`.

Алфавит исключает похожие символы (`0/O`, `1/I`), чтобы игроки не путались.

## Лог и Discord

**redeems.log** (включается `log-redeems`) — одна строка на активацию:

```
[2026-11-08 18:30:12] Steve (uuid) -> SUMMER
```

**Discord webhook:**

1. В Discord: Настройки канала → Интеграции → Вебхуки → создайте вебхук и скопируйте URL.
2. В `config.yml`:

```yaml
discord-webhook:
  enabled: true
  url: "https://discord.com/api/webhooks/..."
  content: "🎁 **%player%** активировал промокод **%code%** (%uses%/%max%)"
```

3. `/mcodes reload`.

Упоминания (`@everyone` и т.п.) в сообщении отключены. Цветовые коды `&` вырезаются. **Не публикуйте URL вебхука.**

## Готовые сценарии

**Одноразовый подарок для всех новичков**

```yaml
WELCOME:
  max-uses: -1
  max-uses-per-player: 1
  rewards:
    - type: item
      material: BREAD
      amount: 16
```

**Промокод блогера на 100 активаций, неделя действия**

```
/mcodes create BLOGGER
/mcodes setuses BLOGGER 100
/mcodes setexpire BLOGGER 7d
/mcodes addcmd BLOGGER give %player% diamond 10
```

**Код только для VIP**

```
/mcodes create VIPGIFT
/mcodes setperm VIPGIFT miragecodes.vip
/mcodes setcase VIPGIFT true
/mcodes addcmd VIPGIFT give %player% netherite_ingot 1
```

**Ивент: код начинает работать в определённый момент**

```
/mcodes create EVENT
/mcodes setstart EVENT 2026-12-24 18:00
/mcodes setexpire EVENT 2026-12-26 18:00
/mcodes addbroadcast EVENT &c%player% &fзабрал подарок ивента!
```

**Награда с шансом и задержкой**

```yaml
rewards:
  - type: item
    material: DIAMOND
    amount: 4
    chance: 25             # выпадет в 25% случаев
  - type: broadcast
    delay: 40              # через 2 секунды
    text: "&c%player% &fактивировал &c%code%&f!"
```

**Выдача валюты и прав через команду** — команда выполняется от консоли, поэтому подойдёт любой плагин:

```yaml
- type: command
  command: "eco give %player% 1000"
- type: command
  command: "lp user %player% parent add vip"
```

## Частые вопросы и проблемы

**Игрок пишет `/code ABC`, а в ответ «Такого промокода не существует».**
Проверьте ID через `/mcodes list`. Если у кода включён `case-sensitive`, регистр должен совпасть точно.

**Код есть, но «отключён».**
`/mcodes toggle <код>`. Также код отключается автоматически, если в `codes.yml` указана неверная дата — смотрите предупреждение в консоли при старте.

**В консоли предупреждение «награда #N — ...».**
В награде ошибка (пустая команда, неизвестный материал, неизвестный тип). Исправьте `codes.yml` и сделайте `/mcodes reload`. Такая награда при активации будет пропущена.

**Команда-награда не сработала.**
Проверьте её отдельно в консоли. Если выбран `as: player`, у игрока должно быть право на эту команду.

**Алиасы `/код` и `/промокод` не подсказываются в чате.**
Клиент Minecraft не подсказывает кириллические команды, но сервер их выполняет. Ввод `/code` подсказывается как обычно.

**Предмет не выдаётся, а падает на землю.**
Инвентарь полон и включён режим `drop`. Переключите `inventory-full: deny`, если хотите блокировать активацию.

**Как узнать, сколько раз использован код?**
`/mcodes list` или `/mcodes info <код>`.

**Как сбросить использования?**
`/mcodes reset <код>` — для всех, `/mcodes reset <код> <игрок>` — для одного игрока (игрок должен был хотя бы раз зайти на сервер).

**Можно ли править `codes.yml` на работающем сервере?**
Да, затем `/mcodes reload`. Но не редактируйте `usage.yml`, а команды `/mcodes ...` во время ручной правки лучше не использовать.

**Данные пропадут при обновлении плагина?**
Нет, `config.yml`, `codes.yml` и `usage.yml` остаются. Недостающие сообщения новых версий берутся из встроенного `config.yml` автоматически.
